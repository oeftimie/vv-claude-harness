## Mistakes
- First AC1 evidence run double-captured events: forgot the installed vv-harness plugin's hooks also fire in a scratch project, so old-code lines (summary/tool_name) landed in the same log as new-code lines. Caught by inspecting log keys; fixed with per-project enabledPlugins=false.
- Three consecutive evidence runs missed the two-spokes-live window before I stopped and re-derived the actual timing constraints (untrusted workspace silently dropping permissions.allow; subagents backgrounding sleeps). Should have read the CLI's "Ignoring 5 permissions.allow entries" warning on run one instead of after run three.
- Put the basic-auth secret shape in a field (`command`) the old summary path never logged, making one red assertion pass trivially; noticed via the red-run output and moved it to `description`.

## Learnings
- A numeric AC ratchet (total assertions strictly below baseline) forced an honest subsumption analysis when the first green came out +1; "expected to shrink" prose would have let it slide.
- Per-project `enabledPlugins: {"name@marketplace": false}` in .claude/settings.json cleanly suppresses an installed plugin for one directory -- the right tool for testing plugin-shipped hooks from a checkout.
- Headless `claude -p` in an untrusted directory ignores that project's permissions.allow entirely (warning on stderr); trust via ~/.claude.json projects[path].hasTrustDialogAccepted.
- kill -0 works for liveness polling of bash background children (bash reaps and caches status on SIGCHLD; no zombie false-positive).
