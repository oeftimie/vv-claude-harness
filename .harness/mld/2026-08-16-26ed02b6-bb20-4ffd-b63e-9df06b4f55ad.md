## Mistakes
- Wrote five timeline positions as `'<'` believing it meant "start with the previous tween". It means *previous end*; `'<<'` is previous start. Caught by reading the bundle, not by testing -- the failure mode is silent and looks plausible on screen.
- Shipped an initial CSS pass where animated-in elements started hidden in the stylesheet, which contradicted my own written policy in analysis/site-plan.md that content must survive a JS failure. Caught only because I ran an explicit no-JS/reduced-motion check afterwards; the policy alone did not stop me writing the violation.
- Ran a reindent script whose end-marker contained a newline, so it never matched and every line to EOF got indented. Reverted cleanly, but I should have checked the marker could match a single line before running it over two files.

## Learnings
- A rendered page is not evidence its module loaded, and a moving element is not evidence the animation is correct. Asserting on computed end-state found three real defects (looping `progress` vs `iterationProgress`; anime overwriting a CSS centering transform; absolute rem distances breaking a diagram's meaning at wide viewports) that a screenshot review would have passed.
- Playwright's `browser_run_code_unsafe` can `page.emulateMedia({reducedMotion:'reduce'})`, which turns "verified reduced motion by code inspection" into an actual measurement. Worth reaching for instead of hedging.
- npm registry + jsDelivr's package file API are a fast, authoritative way to pin a library version and enumerate its real exports when the vendor docs site 404s on half its own URLs.
