  after it already failed identically inside the suite -- the suite's own

  trip of pure confirmation.

## Learnings
- A reviewer's mutation-testing observation ("this invariant is killed by
  exactly one assertion") is a direct test-design instruction for the next
  session touching that code -- persisting it as a memory note paid off
  verbatim in F106's canary-based second pin.
- The v5.4.0 tiered-gate design made this whole session materially
  faster: task completions gated in seconds (smoke only), with the full
  suite running exactly three times at the passing-flip commits.
- claude-progress.txt can list a feature as queued that features.json
  already records as passing (F086); trust the structured file.
